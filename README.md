# Invincible Bot v2 🤖 (Perfect Clear First)

GUI는 **왼쪽 콤보 우선 · 오른쪽 PC/콤보 자동 전환**입니다. 오른쪽과 온라인 봇은 내 가비지 큐의 양·도착 시점·예상 상쇄량과 미리보기 전체의 누적 공격량을 보고 PC와 콤보를 선택합니다. 안전하게 버틸 수 있으면 작은 클리어로 배율을 올린 뒤 큰 공격을 내며, 준비 비용이 이득보다 크면 바로 공격합니다. 고정 콤보 수 기준은 없으며, 블록 개수로 PC 가능성을 거르는 조건은 유지합니다. 양쪽의 현재 콤보, PC 횟수, 최근 스핀과 공격량을 표시합니다. [자동 전환 정책](docs/HYBRID_POLICY.md)을 참고하세요. 같은 탐색 깊이와 동시 배치를 유지하며, SRS-X 90/180도 킥과 스핀 보너스 선택을 지원합니다. [적용 규칙과 검증 범위](docs/TETRIO_RULES.md), [PC 정책](docs/PERFECT_CLEAR.md)을 참고하세요.

TETR.IO 및 로컬 환경에서 작동하는 고성능 4-Wide 테트리스 강화학습(RL) 봇 및 시뮬레이터입니다.  
초고속으로 탐색을 수행하는 **Rust 기반의 AI 시뮬레이터 코어 및 로컬 GUI**와, TETR.IO 커스텀 룸에서 플레이할 수 있는 **TypeScript/Bun 룸 클라이언트**로 구성되어 있습니다.

작은 4-wide 콤보 필드에는 **별도의 상태 전환표 솔버**를 사용합니다. 1,026개 보드 상태와 홀드·7-bag 전환을 미리 계산하고, 실제 미리보기의 소거 경로를 전부 탐색합니다. 가비지 큐가 비었을 때 콤보 유지에 적용하며 PC와 가비지 방어, 높은 필드의 배율 공격 계획은 유지합니다. 무한 콤보를 보장하지는 않습니다. 깊이 설정은 기존 빔 탐색에 적용되고, 전환표 솔버는 전체 미리보기를 사용합니다. [알고리즘·실험 결과·재현 방법](docs/COMBO_SOLVER.md)을 참고하세요.

## 🚀 주요 특징 (Features)

온라인 봇은 기본 **일반 모드**입니다. 방장 또는 초대한 사람이 `!expert`를 입력하면 콤보 전환표를 사용하는 **전문가 모드**로 전환하며, 다시 입력하면 일반 모드로 돌아옵니다. `!expert on` / `!expert off`로 직접 지정할 수도 있습니다. 다음 판단부터 적용되고 해당 방의 다음 라운드에도 유지되며, `!bot`에서 현재 모드를 확인합니다. PPS 상한은 두 모드 모두 5입니다.

전문가 모드는 전환표를 사용할 수 없는 높은 필드·가비지 상황에서도 콤보 우선 탐색을 사용합니다. 예상 가비지 수신량이 같다면 연속 소거를 PC·백투백 공격량보다 우선합니다. SDK의 긴 내부 큐는 앞의 미리보기 5개만 사용합니다. 일반 모드와 오른쪽 GUI의 PC/공격량 전략은 별도로 유지합니다.

`!funny`는 **백투백 쌓기 모드**입니다. 스핀 소거와 테트리스를 노리고 백투백을 끊는 일반 소거를 피하며, 필요하면 줄을 지우지 않고 준비합니다. `!funny on` / `!funny off`도 지원합니다. Funny와 Expert 중 하나를 켜면 다른 모드는 꺼지고, 현재 모드를 다시 토글하면 일반 모드로 돌아갑니다. 가비지를 받지 않기 위한 긴급 소거는 허용합니다.

1. **초고속 AI 탐색 (Lookahead Engine)**
   - **깊이별 전역 빔 탐색**: 각 깊이에서 최대 64개 상태를 확장하여 탐색량을 제한합니다. 착지 모양과 도달 상태의 중복을 제거하고 평가값을 재사용합니다.
   - **알려진 다음 블록만 탐색**: 임의의 블록을 생성하지 않으며, 빈 홀드가 소비하는 다음 블록까지 고려합니다. [검증 결과와 재현 방법](docs/SEARCH_IMPROVEMENTS.md)을 참고하세요.
2. **비동기 멀티스레딩 GUI**
   - AI 탐색 연산을 GUI 렌더링 스레드와 분리하여 로컬 GUI가 **60 FPS** 고정으로 끊김 없이 쾌적하게 렌더링됩니다.
3. **SRS-X 회전과 스핀 판정**
   - **SRS-X 킥과 I 회전 중심 수정**: 90도/180도 킥 순서를 참조 데이터와 대조합니다. 실제 회전으로 도달한 스핀과 일반 배치를 구분합니다. 로컬 가비지 타이밍·Surge는 근사 모델이며 온라인 전체 동작 일치를 보장하지 않습니다.
   - **가비지 상쇄 및 상승 시뮬레이션**: 상대방으로부터 온 가비지를 감지하여, 이를 상쇄(Cancellation)하거나 하단에서 가비지가 올라오는 현상을 예측하여 생존력을 극대화합니다.
4. **퍼펙트 클리어 우선**
   - **PC 수순 탐색**: 콤보 점수보다 필드를 완전히 비우는 수순을 우선합니다. PC 후보가 없으면 보드 평가로 다음 수를 선택합니다.
   - **PC 이벤트 집계**: 실제 줄 삭제 후 필드가 빈 경우에만 집계하며, 로컬 대전에도 PC 공격 보너스를 적용합니다.
5. **안정적인 입력 스케줄러**
   - **1프레임 간격 개별 입력**: 연속 동작이 한 프레임에 뭉개지지 않도록 키 이벤트 사이에 안정적인 프레임 Gap을 확보하여 입력 유실을 방지합니다.
   - **중복 탐색 차단 (Lock-based Planning)**: 미노가 완전히 락킹(Lock)된 후 다음 미노의 연산을 시작하도록 방지하여, 공중에서 미노가 겹쳐 탑아웃되는 오류를 제거했습니다.
6. **온라인 방 설정과 리플레이 관리**
   - 봇에게 방장을 넘기고 `!setup`을 입력하면 가로 4·높이 26·SRS-X만 설정한 뒤 방장 권한을 돌려줍니다. PC 공격량과 스핀 등 나머지 방 설정은 유지합니다. 마지막 사람이 나가면 바로 퇴장합니다. PPS 상한은 5, 기본 워커는 20개 방이며 각 워커가 독립적으로 탐색합니다. 대국은 기간·개수·용량 제한 없이 로컬 `.ttrm`으로 저장합니다. [운영 정책](docs/SERVICE_POLICY.md)을 참고하세요.

## 🧠 이론적 배경 및 알고리즘 설계 (Theoretical Background)

이 프로젝트는 고속 탐색 트리 Pruning 기법과 강화학습 방법론을 결합하여 실시간 1v1 대전 Tetris 환경에서 강건한 에이전트를 구축하였습니다. 적용된 핵심 이론적 배경은 다음과 같습니다:

### 1. 상태 중복 제거
현재 탐색은 보드, 홀드, 전체 미리보기, 콤보, 가비지 및 B2B 상태를 키로 사용하고, 해시가 같아도 실제 키가 같은지 확인합니다. 회전 표기가 달라도 같은 칸에 놓이고 스핀 분류까지 같은 미노는 이동 생성 단계에서 중복 제거합니다. 기존 Zobrist 탐색은 비교용 `find_best_move_original`에 남아 있습니다.

### 2. 깊이별 전역 빔 탐색
각 노드마다 여러 자식을 재귀 탐색하던 구조를 깊이별 전역 빔으로 바꿨습니다. 깊이마다 최대 64개 부모만 확장하며, 상태 평가를 정렬 비교 안에서 반복하지 않습니다. 후보 생성량은 빔 너비 W, 깊이 D, 평균 이동 수 B에 대해 대략 O(D × W × B)이며, 별도로 후보 정렬 비용이 듭니다.

### 3. 탐색 범위와 퍼펙트 클리어
요청된 깊이와 실제 알려진 블록 수 안에서 탐색합니다. 빈 홀드를 처음 사용하면 블록 하나를 추가로 소비하므로 모든 후보에 공통으로 안전한 깊이를 사용합니다. PC 정책은 PC를 찾은 가장 이른 깊이에서 그 수순을 선택하며, 미리보기가 끝나면 임의의 7-bag를 만들어 연장하지 않습니다.

### 4. PC 우선 수순 비교
게임 오버 후보는 제외하고 가장 이른 탐색 깊이에서 발견한 PC를 우선 선택합니다. PC 이전의 후보는 콤보 보상을 제외한 보드 평가로 정렬하므로 줄을 지우지 않는 준비 수도 탐색합니다. 왼쪽 GUI는 `Objective::Combo`로 콤보를 유지하고, 오른쪽과 기본 검색 진입점은 PC 정책을 사용합니다. 빔 탐색이므로 모든 PC 수순의 발견을 보장하지는 않습니다.

### 5. 메타 정책 네트워크 (Meta-Policy Network)
고정된 정적 가중치(Static Weights)는 전술 변화(예: 수비형 플레이, 가비지 상쇄, 공격 집중 등)에 유연하지 못합니다.
- **구조**: Multi-Layer Perceptron(MLP) 기반의 메타 에이전트가 아군과 적군의 보드 높이, 구멍 개수, 쌓인 가비지 정보 등 6개의 매크로 피처를 실시간으로 받아 들여 상황 맞춤형 가중치를 동적으로 출력합니다.
- **잔차 학습(Residual Learning) 적용**: 기본 최적화 가중치를 기준점으로 두고 네트워크가 변동 델타(Delta Offset) 값을 계산하도록 구현함으로써 학습의 수렴성과 안정성을 보장합니다.

현재 저장소에는 학습된 `meta_net.json`이 포함되어 있지 않습니다. 온라인 어댑터는 파일이 없으면 기본 평가 가중치를 사용하고, 대전 GUI 역시 기본값으로 시작합니다. 메타 신경망 학습기의 GUI/CLI 연결과 저장 기능은 별도 구현이 필요합니다.

### 6. 유전 알고리즘 & CMA-ES 최적화
전통적인 경사하강법(Gradient Descent)은 테트리스의 불연속적인 보상 함수와 넓은 상태 공간에서 지역 최적점(Local Minima)에 빠지기 쉽습니다.
- **Separable CMA-ES**: 다변량 정규 분포로부터 모델 파라미터 후보군을 샘플링하여 시뮬레이션을 돌려 피트니스(Combo 달성도, 생존율)를 평가하고, 엘리트 후보들의 방향으로 분포의 평균과 분산(Covariance)을 진화(Evolution)시켜 비선형적인 조합에서도 강건하게 전술 모델을 학습시킵니다.

## 🛠️ 실행 방법 (How to Run)

### 1. 로컬 GUI 시뮬레이터 실행 (Rust)

로컬에서 봇의 탐색 과정과 시뮬레이션을 GUI 환경에서 직접 시청하고 테스트할 수 있습니다. 두 가지 버전이 제공됩니다:

* **통합 대시보드 (싱글플레이어 / 트레이닝 / 배틀 통합)**:
  ```bash
  cargo run --release --bin four_wide_bot
  ```

* **1v1 봇 대전 전용 아레나 (두 봇의 4-Wide 난타전 관전 전용)**:
  ```bash
  cargo run --release --bin battle-gui
  ```

### 2. SSH 서버에서 빌드·호스팅

Linux 서버에서는 계정 설정(`tetrio-bot/.env`) 후 저장소 루트에서 `./up.sh`를 실행하면 GUI 없이 컴파일하고 봇을 시작합니다. `./up.sh status`, `./up.sh logs`, `./up.sh stop`으로 관리합니다. 재부팅 후 자동 실행을 위한 systemd 설정과 설치 순서는 [호스팅 가이드](docs/HOSTING.md)를 참고하세요.

### 3. TETR.IO 봇 클라이언트 직접 실행 (Bun / TS)

TETR.IO 서버에 로그인하여 커스텀 멀티플레이어 룸에서 봇을 구동합니다.

#### 사전 요구사항:
- [Rust](https://www.rust-lang.org/) 및 Cargo 설치
- [Bun](https://bun.sh/) 설치

#### 단계별 실행:

1. **Rust 어댑터 바이너리 빌드**
   ```bash
   cargo build --locked --release --no-default-features --bin triangle-adapter
   ```

2. **TETR.IO 봇 디렉토리 이동 및 의존성 설치**
   ```bash
   cd tetrio-bot
   bun install --frozen-lockfile
   ```

3. **환경 변수 파일 생성**
   `tetrio-bot` 폴더 내에 `.env` 파일을 생성하고 아래 형식을 채워 넣습니다:
   ```env
   BOT_USERNAME=your_tetrio_bot_username
   BOT_PASSWORD=your_tetrio_bot_password
   ```

4. **봇 실행**
   ```bash
   bun run index.ts
   ```

   봇이 성공적으로 로그인하면 TETR.IO 커스텀 룸 초대를 대기합니다. 초대 시 가로 너비가 `4`인 방에서 실시간으로 6-ply 탐색 4-wide 플레이를 보여줍니다.
